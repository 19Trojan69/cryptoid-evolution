# Projectile scene-copy verification

Developer-only tools; no route/build input, debug global or live data is shipped.

The normal frontend build includes the three exact-publisher cases. verify-scope.mjs
restores the one accepted statement and compares the complete pinned GamePage and
21 protected sources. It requires no broadened controller whitelist.

Prepare original hulls with the existing prepare:hulls script before local native
testing. verify-flow.mjs uses existing Playwright WPE2336, original fonts/assets,
actual GamePage/loop/presenter and the real backend handler harness. Backend types
and dependencies must be prepared; no real MongoDB, Pi login, payment or account
is contacted. It intercepts local SDK/API traffic and advances native clocks.
Keep the prepared hull manifest until the run completes, then restore its tracked
generator output. Native libraries use the already-restored official local set.

Final results/flow/native.json has 74 checks. Initial-intro-assumption and the
preliminary player-only run are separated from final live-hostile acceptance.
Screenshots, browser caches/registries, dependencies and temporary pages remain
local intermediates. JSON contains only synthetic player/handler evidence.

verify-public-release.py before COMMIT TREE checks the preceding real public code,
including its two copied arrays. Its after mode verifies the new source/tree,
removed copies, direct presenter, prior guards, byte-equal bundles/CSS between
projects and separate public network/catalogue responses. It does not sign in,
start a live game, inspect private diagnostics or perform any transaction.

Operation counts and local native fixtures do not measure physical phone heat,
energy, native RSS or the cause of a historical White Screen.
