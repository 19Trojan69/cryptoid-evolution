# Boss explosion stability — Testnet

Report: Pi Browser returned to the start page during/at the end of the boss explosion. The account checkpoint preserved the defeated boss and the waiting heart. No deliberate navigation is present in that transition. The precise device-side crash cause is not proven: no native WebView crash or GPU-memory trace is available.

Targeted mitigation: previously the final blast's 16 full-hull clipped/animated copies plus expanding blurred fire/smoke were mounted throughout the five-second descent, although not visible yet. The final blast now mounts only at its original five-second deadline. Its timer is rebased once without changing its original removal deadline. Pauses continue to shift the simulation timeline. A conservative 48 MiB RGBA backing-surface estimate limits fragment count and blast dimensions, considering device pixel ratio, actual hull geometry and viewport. Small/high-DPI layouts use at most eight fragments and four descent fire sites; larger hulls can receive four or no fragments if necessary. Desktop low-DPI layouts can retain sixteen. Optional blur/drop-shadow intermediates are removed on small/high-DPI boss effects. This estimate is a presentation budget, not a measurement or guarantee of total browser memory.

Boss damage, sound cues, scores, Shards, life limits, physical pickup, reward saves, bonus progression and all 50 bosses retain their existing logic. No automatic restart, route change, extra inventory, life refill or production publication is introduced.

Validation: frontend TypeScript/Vite build and release locale checks passed. The full frontend gameplay/locale regression suite passed (336 tests). Six targeted budget/timing/pickup/actual-GamePage tests cover all 50 bosses, eight viewport layouts, DPR 1–4 and reduced effects. Existing game-loop tests cover pause/recovery on errors without losing run state. The integration test executes the actual GamePage destruction function and checks its saved reward state and bounded delayed effect. The single wreck image is requested during descent so deferred layer creation does not introduce a late image request.

Required real-device confirmation: replay this explosion in Pi Browser on the affected device, including audio/mute, foreground/background, reward pickup and the bonus round. No physical Pi Browser/GPU test is claimed and the original crash is not yet conclusively reproduced or resolved.
